### Q4 — 과적합 진단 (에폭 스캔)

#### Kaggle 점수 추이

---

#### WandB 실측 데이터 (600ep + 700ep 런)

**val mAP 추이 (700ep 기준):**

```
ep150 : 0.6165   ← Phase 아직 학습 중
ep200 : 0.9604   ★ 빠른 도약 완료
ep250 : 0.9625   수렴 시작
ep300 : 0.9669   소폭 개선
ep344 : 0.9736   ← 700ep run 내 best 체크포인트
ep400 : 0.9712   ⚠ 정체
ep450 : 0.9684   ⚠ 정체
ep500 : 0.9722   미미한 개선
ep550 : 0.9744   ← ep350 대비 +0.0008 (200ep 소비)
ep600+: 0.9718↓  ⚠ 하락
```

→ **ep350~ep550 사이 200 에폭 동안 mAP 상승폭이 +0.0008밖에 안 됨.** 사실상 plateau.

---

#### overfit/loss_gap 분석 (700ep 기준)

```
ep1   : gap = -4.94  (train >> val, augmentation 신호 풍부)
ep351 : gap = -0.47  줄어드는 중
ep551 : gap = -0.12  ⚠ 거의 수렴
ep651 : gap = -0.11  ← 수렴 완료
```

| gap 의미 | 해석 |
|---|---|
| 크게 음수 | train loss가 val loss보다 훨씬 큼 → augmentation 신호 살아있음 |
| 0에 수렴 | 모델이 데이터의 다양성을 다 학습 → 더 돌려도 신호 없음 |

**600ep 기준 수렴 시점 ≈ ep474, 700ep 기준 ≈ ep524.** 평균 ~ep499.

---

#### 핵심 발견 — val_loss로는 과적합 감지 불가

```
val_loss: 600ep 기준 ep597까지 계속 감소
          700ep 기준 ep669까지 계속 감소
          → "val_loss가 오르면 과적합"이라는 고전적 방법 이 프로젝트에선 작동 안 함
```

| 지표 | 상태 | 사용 가능? |
|---|---|---|
| val_loss | 700ep까지 계속 감소 | ❌ 과적합 감지 불가 |
| val mAP@50 | ep200부터 1.0 고정 | ❌ 포화로 평가 불능 |
| **Kaggle score** | ep250 이후 하락 | ✅ **유일한 진짜 신호** |

**loss_gap은 메커니즘 설명용, 과적합 감지 아님**  
gap이 0에 수렴한다는 건 "augmentation으로 만든 어려운 이미지까지 다 학습 → train ≈ val → 데이터 다양성 소진"을 뜻함. Kaggle 점수 하락이 과적합 증거이고, gap은 왜 그렇게 됐는지 이유를 설명.

ep200 이후 val set(~37장)이 train 분포를 완전히 커버 → 지표 포화.  
val mAP 0.97이어도 Kaggle 0.936 — val 지표를 믿으면 안 됨.

**Q4 결론: 최적 epoch = 250. 에폭 늘리는 건 의미 없음. 병목 = 데이터 다양성.**

### Q5 — 현재 진행 중 (두 갈래 병렬)

#### 실험 설계 배경 및 핵심 가설

Q4에서 확인한 것:
- ep350부터 val mAP 상승폭 **+0.0008 / 200에폭** — 사실상 plateau
- `overfit/loss_gap` ep351(-0.47) → ep651(-0.11)로 수렴 → 데이터 다양성 소진
- Kaggle 점수는 ep250이 피크, 이후 에폭 늘릴수록 하락

**가설: 합성 데이터로 다양성 늘리면 ep350 이후에도 Kaggle 점수가 계속 오른다**

```
기존:
  ep250 → 0.94325  ← 피크
  ep350 → plateau 진입 (gap -0.47로 수렴 중)
  ep500 → 0.93593  ← 역전

synth 추가 시 기대:
  ep250 → 기존 피크 이미 넘음
  ep350 → gap 여전히 -0.2 이상 유지 (데이터 다양성 살아있음)
  ep400 → Kaggle 계속 상승
```

**400ep를 설정한 이유**: 기존에 ep350부터 꺾이기 시작했으므로, 그 이후에도 계속 오르는지 확인하려면 최소 ep400까지 봐야 함. early_stop 비활성화한 것도 곡선 전체를 보기 위해서.

**성공 기준**: ep350 이후에도 Kaggle 점수가 0.94325(기존 250ep 피크)를 넘으면 plateau 연장 입증.  
**WandB 확인 포인트**: 기존 700ep의 ep350 시점 gap(-0.47)보다 더 음수면 데이터 다양성 효과.

#### 실험A — 합성 데이터 (`feature/synth-aug-400ep`)

- **목적**: 데이터 다양성 확보 → plateau 시작점 ep250 → ep400+ 이상으로 미루기
- **설정**: YOLO11x, 640px, batch=8, 400ep, early_stop 비활성화
- **합성 데이터**: GrabCut 알약 크롭 770개 + 배경 패치 390개 → 합성 3000장
  - 역빈도 가중치: 희귀 클래스 알약이 자주 합성에 선택됨
  - val에는 넣지 않음 (train 다양성 전용)
- **검증 방법 (이중 확인)**:
  1. **val mAP @ 같은 에폭 비교** — ep250/ep300/ep350 시점의 val mAP를 기존 700ep 런의 동일 에폭 값과 비교. 기존보다 높으면 synth 데이터가 학습에 도움을 주고 있다는 신호.
     - 기존 700ep 기준값: ep250=0.9625, ep300=0.9669, ep350=0.9736
  2. **Kaggle 점수** — 주요 체크포인트(ep250, ep350, ep400)에서 제출. ep250 기준선(0.94325)을 넘으면 plateau 연장 입증.
  3. **train_loss 곡선 참고** — synth 추가 시 train_loss가 기존 700ep 런보다 같은 에폭에서 더 높게 유지되면 ("더 어려운 샘플을 아직 학습 중") 다양성이 살아있다는 보조 신호. val_loss는 단독으로 판정 불가(계속 감소하므로), train_loss 추이를 함께 비교하는 용도.
  - 최종 판정 우선순위: Kaggle score > val mAP > train_loss 추이. loss는 보조 참고용

#### 실험B — 해상도 비교 (별도, 다른 팀원) — WandB: `q5_yolo11x_img1280_e200_b4_lrhalf_wd0001`

- **가설**: 해상도를 높이면 각인/텍스트 세부 특징이 더 잘 보존되어 클래스 구분력이 향상된다
- **근거**: 640px 200ep(0.94061) → 1024px 200ep(0.94861), 해상도만 올렸더니 +0.008 이미 확인
- **설정** (WandB 실측):
  - img_size: **1280**, epochs: **200**, batch_size: **4**
  - Phase1/2 LR: **5e-5** / Phase3 head: **5e-6** / backbone: **5e-7**
  - early_stop: **없음** (구 기준 실험 — 얼리스탑 도입 전)
  - synth 없음, 원본 데이터만
- 현재 WandB 상태: killed (중간 종료)

#### main — 파이널 런 (실험 아님)

- **배경**: 해상도 실험에서 +0.008 이미 확인됨. 실험 결과 기다리지 않고 시간 없어서 파이널로 선제 실행.
- **설정**: YOLO11x, **1280px**, batch=4, LR 절반(Phase1/2: 5e-4, Phase3 head: 5e-5, backbone: 5e-6), 1500ep, early_stop patience=50, delta=0.03
- **synth 없음** — 원본 데이터만

## 3-Phase 학습 전략 (공통)

```
Phase 1 = 전체 × 0.2   → main: 300ep / feature: 80ep
Phase 2 = 전체 × 0.4   → main: 600ep / feature: 160ep
Phase 3 = 나머지 0.4   → main: 600ep / feature: 160ep
```

| Phase | 열린 레이어 | EMA | 특이사항 |
|---|---|---|---|
| 1 | cv3 last Conv2d만 | OFF | 새 분류 레이어 먼저 수렴 |
| 2 | Detect Head 전체 | **ON (새로 시작)** | bbox + 분류 동시 최적화 |
| 3 | 전체 (backbone LR = head × 1/10) | **리셋** | warmup 5ep, BN eval 5ep 유지 |
