후처리 하이퍼파라미터
-후처리 실험에서는 Ultralytics NMS를 적용 conf_threshold, iou_threshold, max_detections, class-aware/class-agnostic NMS를 비교

이 과정에서 후처리 옵션만으로는 큰 성능 개선을 만들기 어렵고, 모델/checkpoint가 바뀔 때마다 score 분포가 달라질 수 있다는 점을 확인

즉 후처리는 학습 중 계속 바꾸는 변수가 아니라,
최종 모델이 나온 뒤 precision/recall 균형을 맞추는 검증 단계

-하이퍼 파라미터
이전 하이퍼파라미터 실험에서 작은 batch는 loss oscillation을 키울 수 있고,
해상도를 올리면 GPU 메모리 때문에 batch size가 줄어든다는 점을 확인했다.

1280 실험은 img_size 증가로 batch=4를 사용해야 하므로,
기존 lr을 그대로 쓰면 학습이 불안정해질 수 있다.

그래서 1280 highres 실험에서는 batch 감소에 맞춰 lr을 0.5배로 낮췄다.
구체적으로 phase1/2 lr은 0.0001 → 0.00005,
phase3 head lr은 0.00001 → 0.000005,
phase3 backbone lr은 0.000001 → 0.0000005로 조정했다.

이 실험은 단순히 해상도만 올린 것이 아니라,
고해상도 + 작은 batch 조건에서 학습 안정성을 확보하기 위한 lr scaling 실험이다.



**후처리·하이퍼파라미터 실험에서 얻은 기준**

후처리 실험은 단일 옵션으로 점수를 크게 올리기 위한 실험이라기보다, 모델 예측을 Kaggle 제출 형식에 안정적으로 맞추고 모델별 예측 분포를 확인하는 기준을 세운 과정이었다. Ultralytics NMS, confidence threshold, IoU threshold, max detections, class-aware/class-agnostic NMS, bbox clamp, TTA를 비교하면서 후처리 조합만으로 일반화 성능을 크게 끌어올리기는 어렵다는 점을 확인했다.

그래서 이후에는 학습 중 후처리 조건을 계속 흔들기보다, 좋은 checkpoint가 나온 뒤 F1 curve와 시각화를 통해 confidence threshold를 재확인하는 방식이 더 적절하다고 판단했다. 특히 해상도나 모델 구조가 바뀌어도 Kaggle 제출은 원본 이미지 좌표 기준이므로, 좌표 복원과 submission format 검증은 계속 유지해야 하는 안정화 장치로 볼 수 있다.

하이퍼파라미터 실험은 모델 크기, epoch, batch size, learning rate, weight decay가 학습 안정성과 일반화에 어떤 영향을 주는지 판단 기준을 만든 과정이었다. Q4에서 epoch를 늘릴수록 validation 지표는 좋아 보였지만 Kaggle score는 떨어지는 구간이 확인되었고, val_loss나 val mAP만으로 과적합을 완전히 판단하기 어렵다는 점을 확인했다. 따라서 최종 판단은 Kaggle score, loss 흐름, epoch별 변화, batch size에 따른 학습 흔들림을 같이 봐야 한다.

이 기준은 Q5 전략에도 연결된다. 해상도 실험은 단순히 img_size를 키우는 실험이 아니라, 알약 각인과 텍스트 정보를 더 잘 보존할 수 있는지 확인하는 실험이다. 대신 해상도가 커지면 batch size가 줄어 학습이 불안정해질 수 있으므로 learning rate를 낮춰 보정하는 전략이 필요하다. synth 실험은 epoch를 더 늘리는 방향이 아니라, 데이터 다양성 부족이라는 병목을 완화할 수 있는지 확인하는 실험으로 볼 수 있다.

한 줄로 줄이면:

후처리 실험은 “예측 결과를 안정적으로 제출 형식에 맞추는 기준”을 세웠고, 하이퍼파라미터 실험은 “무조건 오래 학습하는 것보다 Kaggle score와 일반화 흐름을 보고 실험 방향을 정해야 한다”는 기준을 세웠다.
