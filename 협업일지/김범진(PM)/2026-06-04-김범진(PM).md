✍️ 답변:

```
700ep 베이스라인 과적합 확정(val 0.975 vs Kaggle 0.936, ep250=0.943보다 낮음)을 근거로
다음 두 실험을 병렬 설계·구현.

[실험 A — feature/synth-aug-400ep]
  목적: GrabCut 세그멘테이션 합성 증강이 과적합 개선에 효과 있는지 검증
  조건: 640px, batch=8, 400ep, early_stop patience=50, LR 원본값 유지
  변수 격리: 해상도/배치 변경 없이 증강만 다름 → 700ep 베이스라인과 직접 비교 가능
  합성 데이터 전략:
    - GrabCut으로 알약 foreground 분리 → pill_bank(crop + category_id + mask)
    - 역빈도 가중치(max_freq / class_freq)로 희귀 클래스 oversample
    - 합성이미지: 3개 또는 4개 알약만 조합 (테스트 데이터 분포 반영)

[실험 B — main]
  목적: 고해상도(1280px) 학습이 test set 일반화에 미치는 영향 측정
  조건: 1280px, batch=4, LR×0.5(linear scaling), early_stop patience=50
  근거: 1024px > 640px 이미 검증됨. 1280이 원본 해상도(~1001×1267)에 가장 근접.
  배치 4 + LR×0.5 ≈ 배치 8 원본 (linear scaling rule로 추가 실험 없이 처리)

추가 구현:
  - checkpoint.py: epoch_{N}.pt 대신 last.pt 덮어쓰기 (Colab 디스크 오버플로 방지)
  - train.py: --notes argparse 추가 → wandb.init(notes=...) 연결
  - notebook: pill_bank 샘플 20장 시각화 (cell 3-1-1), 합성데이터 분포+시각화 (cell 3-2)
  - train.py: early stopping 구현 (early_stop_patience=0이면 비활성화)
  - predict.py 노트북 셀: Kaggle 제출 후 runtime.unassign() 자동 GPU 해제
```

### [5] 오늘 분석/실험 중 얻은 인사이트나 발견한 문제점은?

✍️ 답변:

```
- checkpoint.py가 매 에폭 epoch_{N}.pt를 저장하고 있었음.
  700ep × ~300MB = ~210GB → Colab 15GB 디스크 즉시 초과.
  last.pt 단일 덮어쓰기로 수정.

- 실험 변수 혼동 위험:
  증강 + 해상도 변경을 동시에 하면 원인 귀속 불가.
  feature 브랜치(증강만)와 main(해상도만)으로 격리해서 해결.

- batch×lr 스케일링 검증:
  배치 4→8로 두 배 늘리면 LR도 두 배 (linear scaling rule).
  반대로 배치 8→4면 LR도 절반. 추가 실험 없이 main에 바로 적용 가능.

- 합성 이미지 알약 수:
  처음에 1~4개로 구현했으나, 테스트 이미지가 3~4개 구성인 점 고려해
  3개 또는 4개로만 제한. 1~2개 조합은 분포 불일치로 오히려 성능 저하 가능.
```
